Enterprise Network Security

Implementasi arsitektur keamanan meliputi isolasi DMZ, enkripsi Site-to-Site IPsec VPN, dan Strict DNS Enforcement.

Task & Design

Latar belakang permasalahan dan justifikasi pemilihan arsitektur.

Business Challenges

  • • Server Exposure: Sebuah Web Server internal perlu bisa diakses publik, sementara data di jaringan LAN utama tetap terlindungi.
  • • Unsecured Branch: Kantor cabang memerlukan akses ke server pusat melalui ISP, tapi solusi seperti leased line terlalu mahal.
  • • Social Media Bypass: Pemblokiran media sosial berbasis IP sering gagal dan pengguna tetap bisa mengaksesnya.

Tech Stack: Mengapa OPNsense?

Pemilihan OPNsense didasarkan pada efisiensi biaya (*cost-effective*) dan fleksibilitas infrastruktur. Sebagai solusi *open-source* berbasis FreeBSD, OPNsense menyediakan kapabilitas *enterprise-grade* seperti IPsec IKEv2 dan fitur Advanced NAT tanpa biaya lisensi mahal seperti pada Fortinet atau Palo Alto. Sangat optimal untuk virtualisasi.

Network Topology Overview

Desain arsitektur lab GNS3 secara keseluruhan.

Topologi ini dirancang untuk mensimulasikan lingkungan jaringan Enterprise yang . Jaringan dibagi menjadi dua lokasi utama yang dihubungkan melalui simulasi Internet (ISP): Kantor Pusat (HQ) yang diamankan oleh OPNsense Firewall, dan Kantor Cabang (Branch) yang menggunakan MikroTik RouterOS. Desain ini bertujuan untuk mensimulasikan tiga keamanan: Isolasi layanan publik (DMZ), Komunikasi antar-cabang terenkripsi (IPsec VPN), dan Kontrol akses pengguna (DNS Sinkhole).

SECURITY PLAN 01
P1

DMZ Isolation

Langkah teknis dan pembuktian isolasi Web Server dari internet publik.

01

Arsitektur Segmentasi (DMZ Zone)

Untuk memitigasi risiko pembobolan, Web Server 192.168.2.6 diletakkan di interface fisik yang berbeda dari jaringan lokal karyawan. Aturan Default Deny yang ada di OPNsense mencegah jika ada penyusup berhasil membobol Web Server mereka tidak bisa melompat ke jaringan internal.

02

Konfigurasi NAT Port Forwarding

Karena Web Server menggunakan IP Private, ia tidak bisa dihubungi langsung dari Internet. Saya membuat Rule Port Forwarding pada antarmuka WAN OPNsense. Rule ini bertugas mendengarkan trafik HTTP di IP Publik OPNsense 103.10.1.2:80, lalu meneruskannya ke IP Private Web Server di zona DMZ 192.168.2.6:80.

03

Final Validation: Public Access (ISP)

Untuk membuktikan sistem berfungsi, saya melakukan simulasi akses dari luar / inernet menggunakan router ISP(anggap router ini adalah pihak luar yang ingin mengakses web Browser). Permintaan web brhasil ditembus dan halaman HTML dari dalam DMZ sukses diunduh dari jaringan publik.

04

Anti-Pivoting Test

Firewall OPNsense secara bawaan dikonfigurasi dengan action Drop. Saat ping dilaukukan, terminal stuck karena paket diam-diam dibuang tanpa memberi jawaban, hal ini membuat ping tidak berjalan sama sekali.

P2

IPsec Site-to-Site VPN

Enkripsi jalur komunikasi antar-kantor melintasi internet publik menggunakan standar IKEv2.

01

Cryptography & Policy Setup

Fase pertama adalah mendefinisikan parameter koneksi IPsec antara OPNsense di HQ 103.10.1.2 dan MikroTik di Branch 180.20.1.2. Tunnel dirancang untuk menjembatani subnet lokal HQ 192.168.4.0/24 menuju subnet Branch 192.168.5.0/24 dan sebaliknya.

konfigruasi berhasil dengan menyelaraskan algoritma Phase 1 & Phase 2 secara pada kedua sisi (AES-128, SHA-1, dan PFS Group 2 / modp1024) serta mirroring aturan routing menggunakan otentikasi IKEv2 Pre-Shared Key (PSK).

Final Validation: Secure Routing

Pengujian konektivitas end-to-end dilakukan antar terminal VPCS di kedua tempat. Fokus utamanya bukan sekadar pada keberhasilan ping, melainkan pada validasi jalur enkapsulasi menggunakan traceroute.

SECURITY PLAN 03
P3

DNS Sinkhole & Port 53 Enforcement

Pemblokiran akses tingkat domain dan pencegahan bypass DNS oleh pengguna.

01

Sinkhole

Untuk mencegah akses ke situs tertentu (seperti media sosial dan platform gaming), saya memanipulasi resolusi DNS lokal. Permintaan terhadap domain tertentu secara paksa diarahkan ke alamat IP 0.0.0.0 sehingga browser pengguna tidak akan pernah menemukan server asli dari situs tersebut.

OPNsense: Unbound DNS
02

Anti-Bypass

Pemblokiran DNS lokal sering kali mudah diakali oleh pengguna dengan cara mengubah DNS di PC mereka ke Public DNS (seperti 8.8.8.8 milik Google atau 1.1.1.1 milik cloudflare). Untuk mengatasi ini, saya menerapkan aturan Firewall yang memblokir semua trafik TCP/UDP Port 53 yang mencoba keluar menuju internet.

03

Final Validation: Client Testing
